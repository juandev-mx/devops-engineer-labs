# Lab - Alertmanager

## Overview

This lab demonstrates the integration of **Prometheus Alertmanager** with a Prometheus monitoring environment to manage, route, and process alerts generated by monitoring rules.

The implementation includes:

* Configuring Prometheus to communicate with Alertmanager
* Creating alerting rules
* Defining alert routing policies
* Configuring multiple receivers
* Classifying alerts using labels
* Triggering and validating active alerts
* Monitoring node availability and memory usage

---

## Objectives

* Install and validate Alertmanager.
* Integrate Prometheus with Alertmanager.
* Create alerting rules.
* Configure alert routing based on team ownership.
* Define multiple notification receivers.
* Validate alert generation and alert states.
* Monitor infrastructure health using Prometheus rules.

##  Prometheus Configuration

Prometheus was configured to:

* Scrape metrics from Prometheus itself.
* Monitor Node Exporters.
* Load alerting rules from a dedicated rules file.
* Send generated alerts to Alertmanager.

### Alertmanager Integration

```yaml
alerting:
  alertmanagers:
    - static_configs:
        - targets:
          - localhost:9093
```

### Rule Files

```yaml
rule_files:
  - "/etc/prometheus/rules.yaml"
```

---

##  Alert Rules

### NodeDown

Triggers when a monitored node becomes unavailable.

```yaml
- alert: NodeDown
  expr: up{job="nodes"} == 0
  for: 10s
  labels:
    severity: critical
    team: global-infra
```

### HostOutOfMemory

Triggers when available memory falls below the configured threshold.

```yaml
- alert: HostOutOfMemory
  expr: node_memory_MemAvailable_bytes{job="nodes"} / node_memory_MemTotal_bytes{job="nodes"} * 100 < 95
  labels:
    severity: warning
    team: internal-infra
```

##  Alertmanager Configuration

Alertmanager was configured with:

### Global SMTP Settings

```yaml
global:
  smtp_smarthost: 'localhost:25'
  smtp_from: 'alertmanager@prometheus-server.com'
```

### Routing Configuration

```yaml
route:
  group_by: ['alertname']
  group_wait: 10s
  group_interval: 2m
  repeat_interval: 1h
```

### Team-Based Routing

```yaml
routes:
  - match:
      team: global-infra
    receiver: global-infra-email

  - match:
      team: internal-infra
    receiver: internal-infra-email
```
