# Lab - Kubernetes & Prometheus

## Overview

This lab demonstrates how to deploy and manage Prometheus in a Kubernetes cluster using Helm. The objective is to install Prometheus components, verify the generated Kubernetes resources, expose Prometheus through a NodePort service, and validate that monitoring services are running correctly inside the cluster.

Through this exercise, core concepts such as namespaces, deployments, services, ConfigMaps, Helm releases, and Prometheus monitoring architecture are explored.

---

## Objectives

* Deploy Prometheus on Kubernetes using Helm.
* Create and manage a dedicated monitoring namespace.
* Verify Kubernetes resources created by the deployment.
* Expose Prometheus using a NodePort service.
* Validate service discovery and monitoring components.
* Inspect generated ConfigMaps and deployments.
* Practice operational monitoring workflows in Kubernetes environments.

## Exposing Prometheus Through NodePort

To access Prometheus externally, the service was exposed using a NodePort configuration.

Example:

```yaml

kind: Service
metadata:
  name: prometheus-nodeport
spec:
  type: NodePort
```

Verification:

```bash

```

## Key Learnings

* Installing Prometheus using Helm simplifies Kubernetes monitoring deployments.
* Kubernetes resources can be managed and validated through kubectl.
* Namespaces provide workload isolation.
* Services enable access to Prometheus components.
* ConfigMaps store monitoring configuration.
* Helm offers lifecycle management for monitoring stacks.
* Prometheus is a foundational component for observability in cloud-native environments.
